# 25.6kHz 压测说明

## 目的
验证当前采样链路在高频下的稳定性，重点观察：
- DMA 读数是否稳定
- raw buffer 是否溢出
- SD 写入与 USB 上传是否互斥生效
- 是否出现明显掉样

## 当前运行方式
- 采样任务仍是周期性轮询
- 当前轮询周期：`1ms`
- USB 活跃时：只走 USB 上传，不写 SD
- USB 不活跃时：恢复 SD 写入

## 传感器当前高频配置
- `LSM6DSOX`
  - 加速度：`±4g @ 833Hz`
  - 陀螺仪：`±2000dps @ 833Hz`
- `H3LIS100DL`
  - `±100g @ 400Hz`
- `QMA6100P`
  - `±4g @ BW_1600`

## 压测步骤
1. 上电，保持 USB 断开
2. 查看 `status` / `flowstat`
3. 观察 SD 是否正常创建并持续写入
4. 连接 USB，等待 CDC ready
5. 再次查看 `status` / `flowstat`
6. 确认 SD 停止写入，USB 开始输出
7. 长时间运行，观察是否有掉样、阻塞或超时
8. 断开 USB，确认 SD 恢复写入

## 观察判据
重点看以下指标：
- `updates`
- `usb_raw_sent`
- `sd_raw_written`
- `drop`
- `high_watermark`
- `queue depth`
- `dmastat` 是否出现 timeout / fail

## 结果判断
- `drop = 0`，且队列不持续逼近上限：稳定
- 队列持续增长：吞吐不足
- `drop` 增加：已经掉样
- DMA timeout 增多：底层读数跟不上

## 结论
`25.6kHz` 属于压力测试档，不等于当前已经验证可长期保真运行。
如果压测中出现 backlog 或 drop，就说明当前架构需要进一步优化。

## 新任务更新

### 1. 目标调整
下一阶段不再只关注“持续轮询 + 被动输出”，而是增加一套**USB 命令触发采集**能力，使电脑端可以主动控制设备采样行为。

目标包括：
- 由电脑端发送命令，控制设备开始采集与停止采集
- 支持指定采集时长，例如采几秒
- 支持指定目标采样频率
- 支持指定输出目标，例如 USB 实时上传或 SD 落盘
- 在采集结束后返回统计信息，用于判断是否掉样、是否堵塞

### 2. 对当前架构的判断
当前架构虽然已经把 app 轮询周期提到 `1ms`，并把传感器 ODR 提到当前代码路径可见高档，但这仍然属于**轮询式采样/调度**。

这意味着：
- 适合做当前阶段的高频链路验证
- 不适合直接作为“严格 25.6kHz 精确定时采样”的最终实现

原因是 `25.6kHz` 的采样周期约为 `39.06us`，明显小于 RTOS 任务级 `1ms` 周期粒度。若要认真验证并长期运行 25.6kHz，更合理的方向应是：
- 用定时器提供精确采样时基
- 用 SPI + DMA 完成数据搬运
- 用 RAM buffer 做采样与输出解耦
- 让 USB / SD 成为消费端，而不是驱动采样端

### 3. USB 与 SD 能力关系说明
如果 USB 通信最终能够稳定承载接近 `25.6kHz` 的原始数据上传，这说明以下链路大概率具备可行性：
- 传感器 -> SPI / DMA
- DMA -> RAM buffer
- RAM -> 数据组织 / 输出前处理

但这**不能直接等价于 SD 卡也一定能稳定存储同等速率数据**。

因为 SD 侧除了平均吞吐外，还要额外面对：
- 文件系统抖动
- 单次写入阻塞
- `f_sync` 带来的停顿
- 卡本身擦写管理延迟

因此，USB 侧高频通过，只能说明“采集主链路”大概率可行；SD 是否可靠，仍需单独做最坏情况下的长时间落盘验证。

### 4. 下一阶段建议任务
建议按以下顺序推进：

1. **增加 USB 命令触发采集能力**
   - 新增开始采集 / 停止采集 / 查询状态命令
   - 支持由电脑端传入采样频率、采样时长、输出目标

2. **增加采集结果统计回传**
   - 返回实际采样点数
   - 返回丢样数
   - 返回 DMA 超时/失败次数
   - 返回最大队列深度
   - 返回 USB 发送量 / SD 写入量

3. **保留当前轮询架构用于控制面验证**
   - 先把“命令控制采样”这层能力跑通
   - 使压测操作可重复、可脚本化

4. **再评估是否升级到底层定时器驱动采样**
   - 若目标是严格的 `25.6kHz` 定时采集
   - 则需要从“周期轮询”逐步升级到“定时器 + DMA 驱动”架构

### 5. 新的压测关注点
除原有 `flowstat` / `status` / `dmastat` 外，下一阶段还应重点关注：
- 命令启动后，采样是否按预期开始
- 到达指定时长后，是否能自动停止
- 指定 USB 输出时，SD 是否正确保持关闭
- 指定 SD 输出时，USB 是否不再抢占 raw buffer
- 改为命令触发后，统计值是否更容易与目标采样参数对应

### 6. 阶段性结论
当前系统已经具备：
- DMA 采样链路
- USB / SD 二选一输出链路
- 高频配置测试基础

下一阶段的重点不再只是“提频”，而是把系统从**持续轮询采样**推进到**受控采样任务**，最终为更严格的 `25.6kHz` 定时采样架构做准备。
