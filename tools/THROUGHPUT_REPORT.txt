2. CSV格式分析
================================================================================

【CSV行格式】

  含datetime格式 (旧版):
    frame_id,datetime,x,y,z\r\n
    |- frame_id: 10位数字 ~= 10B
    |- datetime: YYMMDDHHMMSS = 12B
    |- 逗号x4 + \r\n = 6B
    \- x,y,z数据: ~= 15-18B
    总计: 43 bytes/行 (从文档实测)

  去datetime格式 (新版):
    frame_id,x,y,z\r\n
    |- frame_id: 10B
    |- 逗号x3 + \r\n = 5B
    \- x,y,z数据: ~= 15B
    总计: 30 bytes/行 (从文档: 43->30B)

【CSV产出速率计算】

  含datetime + 96kHz mic:
    LSM ACC:  6664 x 43 =  279.8 KB/s
    LSM GYR:  6664 x 43 =  279.8 KB/s
    QMA:      1600 x 43 =   67.2 KB/s
    H3:        400 x 43 =   16.8 KB/s
    MAG:       100 x 43 =    4.2 KB/s
    ENV:         1 x 43 =    0.0 KB/s
    MIC:     96000 x 2  =  187.5 KB/s
    --------------------------------------
    总计:                   835.4 KB/s

  去datetime + 96kHz mic:
    传感器:   (6664x2 + 1600 + 400 + 100 + 1) x 30 = 452.0 KB/s
    MIC:                                            187.5 KB/s
    ----------------------------------------------------------
    总计:                                           639.5 KB/s ***

  去datetime + 48kHz mic:
    传感器:                                         452.0 KB/s
    MIC:      48000 x 2                          =   93.8 KB/s
    ----------------------------------------------------------
    总计:                                           545.8 KB/s

5. 与SD卡写入上限对比
================================================================================

  SD卡持续写入上限: ~648 KB/s (实测，含GC/PROGRAMMING开销)

  配置                   理论产出    vs 648 KB/s   预测
  --------------------------------------------------------------------
  CSV+datetime+96kHz     835.4       +187.4        [!!] 严重掉帧 ~29%
  CSV+datetime+48kHz     741.6       +93.6         [!]  掉帧 ~14%
  CSV-datetime+96kHz     639.5       -8.5          [OK] 理论安全 (余量1.3%)
  CSV-datetime+48kHz     545.8       -102.2        [OK] 安全 (余量16%)
  BIN+96kHz              399.2       -248.8        [OK] 安全 (余量38%)
  BIN+48kHz              305.5       -342.5        [OK] 安全 (余量53%)

【掉帧根因解析】

  从文档分析得知:
  1. CSV+datetime掉帧根因 = 产出(835 KB/s) > 卡上限(648 KB/s)
  2. 去datetime节省30%产出 -> 降到639.5 KB/s -> 理论贴近安全线
  3. 实测CSV-datetime仍有8.5-11%残余掉帧 (60min长录验证)
     根因: CSV表头~37B导致数据错位，每64KB写跨簇边界拆成
     cnt=127+cnt=1 (RMW)，浪费~32%写时间
     解法: 表头填充#到整簇(65536B)让数据对齐
  4. BIN无表头 + 数据紧凑 -> 399 KB/s远低于上限 -> 零掉帧

6. 数据效率对比
================================================================================

  CSV vs BIN 数据开销:

                        CSV(43B)    CSV(30B)    BIN(14B)    节省
  --------------------------------------------------------------------
  每帧元数据开销        ~25B        ~15B        8B          -
  传感器数据纯payload   ~18B        ~15B        6B          -
  数据/总计比例         41.9%       50.0%       42.9%       -

  vs CSV含datetime:
    去datetime                       23.4%节省
    BIN格式                                      52.2%节省

【BIN优势】
  1. 产出速率低 -> 大幅低于SD卡上限 -> 零掉帧
  2. 定长帧 -> 无CSV文本错位/污染问题
  3. CRC32校验 -> 可检测损坏
  4. 紧凑二进制 -> 节省52%存储

【CSV优势】
  1. 人类可读 -> 无需解析工具
  2. 标准工具支持 (Excel/pandas/etc)

8. 最终结论
================================================================================

【理论计算验证】

  [OK] CSV (去datetime) + 96kHz: 639.5 KB/s ~= 636 KB/s (误差0.6%)
       -> 理论计算准确

  [?]  BIN + 96kHz: 399.2 KB/s vs 425 KB/s (差异6.1%)
       -> 需要实测确认差异来源

【产出 vs 落盘瓶颈】

  卡上限 648 KB/s:
  - CSV+datetime: 超出29% -> 严重掉帧
  - CSV-datetime: 贴近上限 (余量1.3%) -> 轻微掉帧 (实测8-11%)
  - BIN格式: 远低于上限 (余量38%) -> 零掉帧

【推荐方案】

  1. 长时间录制 + 零掉帧要求:
     -> BIN格式 + 96kHz mic (399 KB/s, 余量38%)

  2. 需要CSV可读性 + 可接受轻微掉帧:
     -> CSV去datetime + 表头填充512 + 96kHz (实测8-11%掉帧)

  3. CSV零掉帧:
     -> CSV去datetime + 表头填充 + 48kHz mic (546 KB/s, 余量16%)
     或 BIN格式

【实测验证路径】

  无法访问用户提及的会话数据 (E盘未挂载)。
  完成实测验证需要:
  1. 插入SD卡或提供会话数据路径
  2. 运行: python tools/verify_throughput.py <会话路径>
