# 传感器数据采集系统 — 工作原理说明

## 一句话概括

这个设备同时用 3 个传感器"听"振动和冲击，把数据存到 SD 卡里，就像一个三通道的黑匣子。

---

## 1. 三个传感器各司其职

| 传感器 | 测什么 | 每秒采多少次 | 精度 | 类比 |
|---|---|---|---|---|
| **LSM6DSOX** | 加速度 + 陀螺仪（6 轴） | 6664 次 | 0.122 mg（能感知轻微抖动） | 高清摄像机 |
| **QMA6100P** | 加速度（3 轴） | 1600 次 | 0.488 mg | 手机里的加速度计 |
| **H3LIS100DL** | 加速度（3 轴，高冲击） | 400 次 | 780 mg（只看大冲击） | 碰撞传感器 |

**为什么需要三个？**
- LSM6DSOX 精度最高、速度最快，但量程只有 ±4g，太大冲击会"爆表"
- H3LIS100DL 量程 ±100g，能扛住剧烈撞击，但精度粗糙
- QMA6100P 介于两者之间，量程 ±4g 但速度比 LSM 慢，作为冗余备份

三个一起用，就像同时用显微镜和望远镜看同一个目标——各取所长。

---

## 2. 数据怎么从传感器跑到 SD 卡

整个流程可以用一条管道来理解：

```
传感器芯片 → SPI 总线 → MCU 内存（环形缓冲）→ SD 卡文件
     采            传              暂存              写入
```

### 2.1 第一步：传感器采样

传感器芯片内部有一个叫 **FIFO** 的小仓库（类似快递柜）：

- **LSM6DSOX**：仓库能放 511 个包裹，每包 7 字节（1 字节标签 + 6 字节 XYZ 数据）
- **QMA6100P**：仓库能放 63 个包裹，每包 6 字节（纯 XYZ 数据）
- **H3LIS100DL**：没有仓库，每次只读 3 个字节（X/Y/Z 各 1 字节）

传感器按设定频率往仓库里塞数据。仓库快满的时候（到了"水位线"），会**发一个中断信号**告诉 MCU："我这里满了，快来取！"

```
LSM6DSOX: 水位线 = 256 个 → 大约每 19 毫秒通知一次
QMA6100P: 水位线 = 16 个  → 大约每 10 毫秒通知一次
H3LIS100DL: 没有仓库，MCU 主动每 2.5 毫秒来读一次
```

### 2.2 第二步：MCU 通过 SPI 总线读取数据

SPI 总线就像一条串行传送带，数据一个字节一个字节地传。

**LSM6DSOX 读一次要多久？**
```
水位线 256 个 × 每个 7 字节 = 1792 字节
SPI 速度 = 5 MHz（每秒传 500 万个字节）
1792 字节 ÷ 5 MHz ≈ 0.36 毫秒（纯传输时间）
加上 HAL 驱动开销 ≈ 4.7 毫秒（实际耗时）
```
4.7 毫秒读完，离下次通知还有 14 毫秒，**绰绰有余**。

**QMA6100P 读一次要多久？**
```
水位线 16 个 × 每个 6 字节 = 96 字节
SPI 速度 = 1.25 MHz
96 字节 ÷ 1.25 MHz ≈ 0.08 毫秒
加上开销 ≈ 1 毫秒
```

**H3LIS100DL 读一次要多久？**
```
3 个寄存器 × 每次 2 字节 SPI = 6 字节
6 字节 ÷ 1.25 MHz ≈ 0.005 毫秒
加上开销 ≈ 1 毫秒
```

### 2.3 第三步：把数据转成 CSV 文本，塞进环形缓冲

MCU 读到的是二进制原始数据（比如 `0x1F, 0x20`），需要转成人能读的 CSV 格式。

以 LSM6DSOX 为例，一个样本变成一行 CSV：
```
原始: [tag=02] [82 00] [D5 FF] [00 20] [03 00] [FF FF] [00 00]
                                    ↓ 转换
CSV:  1234,5678,82,-43,8192,3,-1,0\r\n
      帧号  时间  加速度XYZ      陀螺仪XYZ
```

这行 CSV 文本（约 50 字节）被塞进一个叫**环形缓冲**的大仓库里。

### 2.4 第四步：环形缓冲 — 数据的"蓄水池"

环形缓冲就像一个圆形的传送带，一头塞数据、一头取数据：

```
        写入端 (sensor task)
            ↓
    ┌───────────────────────┐
    │ ████████████░░░░░░░░░ │  ← 64 KB 的环形空间
    └───────────────────────┘
            ↑
        读取端 (logger task)
```

三个传感器各有自己的缓冲区：

| 传感器 | 缓冲区大小 | 每秒产生数据 | 能撑多久不取 |
|---|---|---|---|
| LSM6DSOX | **64 KB** | ~333 KB/s | **0.19 秒** |
| QMA6100P | **32 KB** | ~48 KB/s | **0.67 秒** |
| H3LIS100DL | **16 KB** | ~7 KB/s | **2.3 秒** |

**为什么 LSM 只能撑 0.19 秒？** 因为它数据量太大了！每秒 6664 个样本 × 50 字节 = 333 KB。
但没关系，logger 任务每 10 毫秒就会来取一次数据，实际取走的速度远大于 333 KB/s。

**为什么不用更大的缓冲？** 因为 STM32U575 总共只有 256 KB RAM，三个缓冲已经占了 112 KB（44%），剩下的要给程序栈、FreeRTOS 内核和其他变量用。

### 2.5 第五步：Logger 任务写入 SD 卡

Logger 任务就像一个快递员，不停地从三个缓冲区取包裹，然后写入 SD 卡文件：

```
每 10 毫秒循环一次：
  1. 从 LSM 缓冲取一块（最多 16 KB）→ 写入 LSM_IMU.CSV
  2. 从 QMA 缓冲取一块（最多 16 KB）→ 写入 QMA_ACC.CSV
  3. 从 H3  缓冲取一块（最多 16 KB）→ 写入 H3_ACC.CSV
  4. 每写 32 次 → 调用 f_sync 确保数据落盘
```

**为什么是 16 KB 一块？** 这是经过权衡的：
- 太大（如 64 KB）：单次写入耗时长，传感器缓冲可能溢出
- 太小（如 512 B）：频繁写入，FAT 文件系统开销大
- 16 KB 刚好：SD 卡写入 ≈ 4 毫秒，一个循环约 12 毫秒搞定三路

## 3. 时间戳：怎么知道每个数据是什么时候采的？

### 问题

系统时钟精度只有 1 毫秒，但 LSM6DSOX 每秒采 6664 次（每 0.15 毫秒一次）。
如果用系统时钟，很多样本会得到**相同的时间戳**，分不出先后。

### 解决方案

MCU 内部有一个叫 **DWT** 的硬件计数器，每 6.25 纳秒加 1（160 MHz 时钟）。

```
第一个样本: 时间戳 = DWT当前值
第二个样本: 时间戳 = 上一个 + 150 微秒
第三个样本: 时间戳 = 上一个 + 150 微秒
...
```

每个样本的时间戳都是**严格递增**的，永远不会重复，即使被其他任务打断也没关系。

## 4. SD 卡上的文件长什么样？

每次开始采集，系统会自动创建一个新文件夹：

```
SD卡/
├── DEVCFG.JSN          ← 设备配置文件（量程、采样率等）
├── CKBX0001/           ← 第 1 次采集会话
│   ├── CONFIG.JSN      ← 本次采集的配置快照
│   ├── LSM_IMU.CSV     ← LSM6DSOX 的加速度+陀螺仪数据
│   ├── LSM_TMP.CSV     ← LSM6DSOX 的温度数据
│   ├── H3_ACC.CSV      ← H3LIS100DL 的加速度数据
│   └── QMA_ACC.CSV     ← QMA6100P 的加速度数据
├── CKBX0002/           ← 第 2 次采集会话
│   └── ...
```

**CSV 文件内容示例：**

LSM_IMU.CSV（每秒 6664 行）：
```csv
frame_id,tick_ms,acc_x,acc_y,acc_z,gyr_x,gyr_y,gyr_z
1,1023,82,-43,8192,3,-1,0
2,1023,84,-41,8189,2,-2,0
3,1024,80,-45,8195,1,0,1
...
```

- `frame_id`：样本序号（1, 2, 3...）
- `tick_ms`：时间戳（毫秒）
- `acc_x/y/z`：加速度原始值（int16，PC 端乘以 0.122 得到 mg）
- `gyr_x/y/z`：陀螺仪原始值（int16，PC 端乘以 70.0 得到 mdps）

**为什么存原始值不存物理值？** 原始值是整数，CSV 只需要 5-6 个字符。
如果存浮点数（如 `0.122`），每行多 10-20 字节，6664 Hz 下每秒多占 100+ KB。

## 5. 数据量到底有多大？

以默认配置（LSM 6664Hz / QMA 1600Hz / H3 400Hz）采集 5 秒：

| 文件 | 每秒数据量 | 5 秒总量 |
|---|---|---|
| LSM_IMU.CSV | 333 KB | 1.67 MB |
| QMA_ACC.CSV | 48 KB | 240 KB |
| H3_ACC.CSV | 7 KB | 35 KB |
| LSM_TMP.CSV | 1 KB | 5 KB |
| **合计** | **389 KB/s** | **1.95 MB** |

SD 卡写入速度约 3-6 MB/s，**完全够用**。Class10 / U1 级别的卡就行。

## 6. 内存都用在哪了？

STM32U575 有 256 KB RAM，分配如下：

```
┌─────────────────────────────────────────┐
│  环形缓冲区 (112 KB)                     │  ← 数据暂存，最大头
│  ├─ LSM: 64 KB                          │
│  ├─ QMA: 32 KB                          │
│  └─ H3:  16 KB                          │
├─────────────────────────────────────────┤
│  帧缓冲区 (53 KB)                        │  ← USB 上传 + 温度路径
│  └─ 512 帧 × 104 字节/帧                │
├─────────────────────────────────────────┤
│  FreeRTOS 任务栈 (28 KB)                 │  ← 6 个任务各 4-6 KB
├─────────────────────────────────────────┤
│  FreeRTOS 内核 + 堆 (33 KB)             │  ← 调度器、mutex、信号量
├─────────────────────────────────────────┤
│  HAL 驱动 + 其他 (10 KB)                 │  ← SPI/DMA/USB 缓冲
├─────────────────────────────────────────┤
│  剩余 (~20 KB)                          │  ← 安全余量
└─────────────────────────────────────────┘
         总计: ~256 KB (用 87%)
```

**为什么不用 malloc 动态分配？**
1. 嵌入式系统怕内存碎片——运行久了分配不出连续大块
2. FreeRTOS 的 malloc 在中断里不能用——但传感器读取经常在中断上下文
3. 静态分配编译时就知道用多少 RAM，不会运行时突然不够

## 7. 多任务怎么配合？（FreeRTOS）

系统有 6 个任务同时运行：

```
优先级高 ──────────────────────────────── 优先级低

LSM任务    QMA任务    H3任务    USB串口    Logger任务   USB上传
(AboveNormal) (AboveNormal) (AboveNormal) (AboveNormal) (Normal)    (Normal)
  │          │          │          │          │          │
  │ 读FIFO    │ 读FIFO    │ 轮询读     │ 收命令     │ 写SD卡     │ 发USB数据
  │ 写ring    │ 写ring    │ 写ring     │ 发响应     │ 读ring     │ 读帧缓冲
  │          │          │          │          │          │
  └──── SPI1 ────┘   └──────── SPI2 (共享，需 mutex) ────────┘
```

**为什么传感器任务优先级高于 Logger？**
传感器数据产生得快、不能等。如果 Logger 优先级更高，它写 SD 卡时会阻塞传感器任务，导致 FIFO 溢出丢数据。

**SPI2 为什么需要 mutex？**
H3LIS100DL 和 QMA6100P 共用一条 SPI 总线。如果不加锁，两个任务同时发 SPI 命令，数据会乱掉。
